CORE FEATURES
================================================================================

DETERMINISTIC DEDUPLICATION
────────────────────────────────────────────────────────────────────────────
  1. Exact Match:   SHA256(title + URL + DOI + authors)
  2. DOI Match:     Direct comparison
  3. Author Cluster: Same authors + title similarity > 0.85
  4. Semantic Match: Levenshtein distance > threshold
  
  → Output: Map<groupId, sourceIds[]> (reproducible grouping)

DETERMINISTIC RELEVANCE SCORING
────────────────────────────────────────────────────────────────────────────
  - Keyword Match (query tokens ∩ source text):           40%
  - Domain Reputation (hardcoded trusted list):           30%
  - Recency Decay (age_months / 12):                      30%
  - Open Access Bonus:                                    10%
  ─────────────────────────────────────────────────────
  Final Score = min(1.0, sum) | Range: [0, 1]
  
  → No randomization, no ML models, fully deterministic

COMPLETE AUDIT TRAIL
────────────────────────────────────────────────────────────────────────────
  Every operation logged:
    timestamp | stage | action | resultCode | details
  
  Stages: query_validation → fetch → dedup → verify → score
  
  Execution Hash = SHA256(all log entries)
  
  → Enables perfect reproducibility verification

EVIDENCE BINDING
────────────────────────────────────────────────────────────────────────────
  For each (claim, source) pair:
    similarity = (claim_tokens ∩ source_text) / claim_tokens
    if similarity > 0.6:
      EvidenceClaimBinding(
        sourceId, claimId, confidenceLevel, auditHash
      )
  
  → Deterministic linking to diagnostic claims

================================================================================
PERFORMANCE CHARACTERISTICS
================================================================================

  Input Size  |  Execution Time  |  Memory  |  Complexity
  ─────────────────────────────────────────────────────
  10 sources   ~10ms             <1MB      O(n)
  100 sources  ~100ms            ~5MB      O(n) to O(n²)
  1000 sources ~1-2s             ~20MB     O(n²) worst case

  Note: O(n²) only for semantic matching (Levenshtein)
        Exact/DOI shortcuts keep typical case near O(n)

OPTIMIZATION
  - Dedup similarity threshold controls precision/speed tradeoff
  - Batch processing for large source sets
  - Configurable API timeouts
